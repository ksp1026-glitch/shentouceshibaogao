# 渗透测试报告

完整打靶流程记录 —— 从信息收集到提权，最后输出一份结构化报告。

**这和单点漏洞 writeup 的区别**：单点是「这个漏洞怎么利用」，报告是「拿到一台未知机器，我怎么一步步打进去」。

## 报告标准结构

一份完整的渗透测试报告应该包含：

```
1. 执行摘要
   - 测试目标、时间范围、总体风险评级

2. 信息收集
   - 存活主机发现（Nmap）
   - 端口与服务识别
   - 目录/文件枚举
   - 指纹识别（CMS、框架、版本）

3. 漏洞发现与利用
   - 每个漏洞：位置、原理、利用过程、影响

4. 权限提升
   - 从普通用户到 root 的路径
   - 提权手法与原理

5. 风险汇总
   - 按严重程度排序（严重/高/中/低）
   - 每个漏洞的 CVSS 评分思路

6. 修复建议
   - 每一项都要可执行，不能写"加强安全意识"这种空话

7. 附录
   - 使用的工具与命令
   - 时间线
```

## 常用命令速查

```bash
# 主机发现
nmap -sn 192.168.1.0/24

# 端口与服务扫描
nmap -sV -sC -p- -T4 192.168.1.100

# 目录枚举
gobuster dir -u http://target -w /usr/share/wordlists/dirb/common.txt

# 提权信息收集
./linpeas.sh
```
